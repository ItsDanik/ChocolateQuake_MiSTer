# ChocolateQuake hybrid core for MiSTer (Quake)

@hybrid/CLAUDE.md

## This core

- Name everywhere: `ChocolateQuake` (the engine: core, folders `games/dnk/ChocolateQuake/` and `logs/dnk/ChocolateQuake/`, `_Other/dnk/dnk-ChocolateQuake_*.rbf`, release), `chocolatequake` (game submodule, binary in `build/`, log, lock). The games and their menu entries (`_Other/dnk-<title>.mgl`): `package/games.txt` (in the zip as `games/dnk/ChocolateQuake/games.txt`, from which the database's build makes the launcher's catalogue).
- The game is the `chocolatequake/` submodule, branch `mister`. Its MiSTer code is behind the `MISTER_HYBRID` build option.
- Build: `./build.sh` (game), `./core/build_core.sh` (FPGA), `./package.sh` (zip in `dist/`), `MISTER=root@<address> tools/deploy.sh`.
- Release: the zip in `releases/`. Players get it once it is published to the database, only when Danik asks: `hybrid/launcher/distribution.py publish ~/dnk_Distribution_MiSTer releases/ChocolateQuake_YYYYMMDD.zip` (the rule in `hybrid/CLAUDE.md`).
- Try a build on the MiSTer without installing it: `MISTER=root@<address> tools/test_on_mister.sh <id>|list|nodata|log|stop` (the rule in `hybrid/CLAUDE.md`).
- Lines marked `GAME:` in the scripts and `TODO` in the READMEs are the places the template left for this game.

## Quake

- The port is [Chocolate Quake](https://github.com/Henrique194/chocolate-quake) (vanilla Quake 1.09, software renderer), chosen 2026-10-24 for its vanilla features and speed: on the PC its engine took 0.278 ms a frame of demo1 at 320x200, TyrQuake 0.346, qrustyquake 0.350. `chocolatequake/` is the fork [ItsDanik/chocolate-quake](https://github.com/ItsDanik/chocolate-quake), branch `mister` from upstream's edb8209; the core's repository is [ItsDanik/ChocolateQuake_MiSTer](https://github.com/ItsDanik/ChocolateQuake_MiSTer), branch `main` (both made 2026-10-25; until then local only).
- Games (ids are Danik's logo names): `QUAKE` (id1), `HIPNOTIC` (Scourge of Armagon, `-hipnotic`), `ROGUE` (Dissolution of Eternity, `-rogue`); the shareware (id1/pak0.pak alone) has no menu entry, the `QUAKE` entry starts it (`MH_PickGame()`'s `shareware_of`). The mission packs need the full id1. `MiSTer_SelectGame()` adds `-basedir .` and the pack's option. Folders, paks and loose files are found in any case (`ID1/PAK0.PAK` of CD and shop copies: `COM_FindCase()` in `com_fs.c`; loose files, `MUSIC/TRACK02.OGG` too, a part of their path at a time with `COM_FindPathCase()` when the exact name is not there, 2026-10-25: the SD card's exFAT does not tell the cases apart, but ext4 or NTFS drives and `/tmp` do). The 2021 rerelease's own paks are not what this engine reads; its folder of the original files is (Danik accepted that, 2026-10-24; the README says so for Steam and GOG, 2026-10-25).
- Video (`src/video/src/vid_mister.c` in place of the renderer code): the window surface in 8 bits (`SDL_MISTER_VIDEO_FORMAT=INDEX8`) is `vid.buffer` itself, which keeps its pixels as Quake needs: the library's two frame buffers in turn (`SDL_MISTER_DIRECT`, no copy; two pages as Quake's VGA page flipping, the status bar and the border drawn on both; `MISTER_HYBRID_DIRECT=0` copies the frame, one page). The OSD's *Resolution* (bits 24..25: 320x200, 640x200, 320x240, 640x240) is read every frame and changes the mode at once. In the 640-wide modes the 3D view has twice the detail and the 2D (status bar, console, menus, centre prints) is laid out in `vid.width2d` (320) and drawn twice as wide (`Draw_WideBlock()` in `draw.c`); the full-screen routines (tile clear, fade, console background) stay in real pixels.
- 240 lines (`vid.hud_over_view`): the view fills the screen (`VID_VIEW_SB_LINES()`: no lines left to the status bar), the status bar and inventory are drawn over it every frame at the bottom HUD margin (`vid.hud_bottom`), the console's notify lines, the chat line and the ram/net/turtle icons at the top one (`vid.hud_top`). Both HUD lines (Danik, 2026-10-24: top the console and its messages, bottom the status bar), greyed out with mask bit 0 in the 200-line modes. Menus keep Quake's layout from the top of the screen.
- Input: the MiSTer joystick is mapped as a game controller (`IN_AddMiSTerMappings()` in `in_gamepad.c`) and opened at the start (it was there before the mapping, no event says so). The core's buttons bind as Quake keys (`MiSTer_PadBindings()`, run after `default.cfg`, before `config.cfg`): A jump, B swim down, X / Y next / previous weapon (impulse 10 / 12), L and L2 run, R and R2 attack, R3 centerview, Select scores, Start the menu. In menus the game's buttons do nothing (Menu OK / Back are the paddles, K_ENTER / K_ESCAPE, nothing in the game), except while *Customize controls* waits for a button; Menu OK also answers Quake's two questions (new game, quit). MiSTer presses the d-pad with the stick: a d-pad press in the game is dropped while the stick points its way (`IN_StickHoldsDpad()`, a quarter of the way out as `MH_StickDpad()`: the hybrid rule that the left stick only moves and strafes; menus keep it), and the stick's own d-pad emulation is off. Checked on the MiSTer with the stick pushed fully left and right (Danik, 2026-10-25).
- Cheats (`Host_MiSTerCheats()` in `host_cmd.c`, single player only): *God Mode*, *No Clipping*, *Invisible to Monsters* (bits 28..30) run Quake's commands on the local server when the player's state differs, again on every level; triggers *All Weapons and Keys* (impulse 9), *Quad Damage* (impulse 255), *Full Health and Armor* (100 health, 200 red armor; rogue's armor bits), *Next Level* (the level's trigger_changelevel whose map comes first by name: not the secret exit, episode 1 from the start map). All four tried in both mission packs on the PC (2026-10-24).
- Rumble (*Rumble* On / Strong / Off, bits 26..27): hits (`V_ParseDamage`), shots (the view's kick, `punchangle`, heavier for the launchers), landings (land.wav / land2.wav on the player), explosions by distance (`cl_tent.c`); jolts fade out (`MiSTer_Rumble()`), none during demos.
- Music: Chocolate Quake plays CD tracks from `music/trackNN.ogg|mp3|flac|wav`; libvorbis, libFLAC and libmad are not on the MiSTer, so `snd_mister.c` decodes with SDL2_mixer's single-file decoders (stb_vorbis, dr_flac, minimp3, `MISTER_CODECS`). No MIDI: `MIDI_SYNTH` 0.
- Tested on the MiSTer before the first release (2026-10-25, `tools/test_on_mister.sh`, hybrid eb4ae71): `QUAKE`, `HIPNOTIC`, `ROGUE` from the SD card and from USB (`TEST_USB=1`, saves and `config.cfg` written there), `list` and quitting back to it, `nodata` (SD and USB), a mission pack with the shareware alone (its message) and the `QUAKE` entry starting the shareware; Danik checked the start, the menus with Menu OK / Back, the stick, the HUD margins while playing, the cheats and the diagnostic report (read with `diag_read.py`: 640x240, 8 frames never shown in 60 seconds, 6 of them with the OSD open). The span worker waits for work with `sched_yield()` while a frame is drawn, so the report shows CPU1 near 100%; the audio never ran dry.
- `MISTER_HYBRID_FPSLOG=1` prints where a frame's time goes (`MiSTer_Mark()` in `host.c` and `screen.c`).
- **Renderer** (the game's commit `1632798`, 2026-10-24): Chocolate Quake's C (no DOS Quake x86 assembly), made faster for the Cortex-A9 with the same pictures as id's code (every frame of timedemo demo1 hashed, pixels and z buffer, against id's version on the MiSTer: `MISTER_HYBRID_FRAMEHASH`). The span, sprite, polyset and particle drawers and the lit surface blocks keep their globals in registers and start the next piece's divide before the pixels, a span's last step by multiplication (no integer divide in hardware); z spans eight at a time with NEON. `d_spanjob.c`: a worker on CPU1 builds and draws the textured world surfaces with the game thread, and draws the odd rows of the alias models' spans while the game thread draws the even ones (`MISTER_HYBRID_SPANTHREAD=0` without it). `MISTER_HYBRID_PROFILE` and `MISTER_HYBRID_ARGS` for development.
- **Frame pacing** (the rule in `hybrid/CLAUDE.md`; 2026-10-24, demo1's first 50 seconds after the first 5, `MISTER_HYBRID_PACE=1`, runs in turns): with the renderer before its speed-up, at 640x240, without drawing ahead (`MISTER_HYBRID_AHEAD=0`) 199 / 202 frames never shown and 525 / 526 shown twice, with it 40 / 36 and 372 / 363; the render took 16.1 ms a frame on average (slowest about 40 ms). **`DRAW_AHEAD` 1.** Frames per second with it, then: 320x200 59.6, 320x240 59.2 (render 11.5 ms), 640x200 58.1 (12.0 ms), 640x240 53.5. With the faster renderer, the same run at 640x240 with drawing ahead: frames never shown 33 -> 2, shown twice 467 -> 2, the 3D view 17.1 -> 9.0 ms a frame. Not measured again (Danik, 2026-10-25, for the first release): the frames per second of each mode, and the run without drawing ahead on the faster renderer; with 9 ms frames drawing ahead may no longer win by a clear margin, and then the rule says `DRAW_AHEAD` 0.
