# ChocolateQuake hybrid core for MiSTer (Quake)

@hybrid/CLAUDE.md

## This core

- Name everywhere: `ChocolateQuake` (the engine: core, folders `games/dnk/ChocolateQuake/` and `logs/dnk/ChocolateQuake/`, `_Other/dnk/dnk-ChocolateQuake_*.rbf`, release), `chocolatequake` (game submodule, binary in `build/`, log, lock). The games and their menu entries (`_Other/dnk-<title>.mgl`): `package/games.txt` (in the zip as `games/dnk/ChocolateQuake/games.txt`, from which the database's build makes the launcher's catalogue).
- The game is the `chocolatequake/` submodule, branch `mister`. Its MiSTer code is behind the `MISTER_HYBRID` build option.
- Build: `./build.sh` (game), `./core/build_core.sh` (FPGA), `./package.sh` (zip in `dist/`), `MISTER=root@<address> tools/deploy.sh`.
- Release: the zip in `releases/`. Players get it once it is published to the database, only when Danik asks: `hybrid/launcher/distribution.py publish ~/dnk_Distribution_MiSTer releases/ChocolateQuake_YYYYMMDD.zip` (the rule in `hybrid/CLAUDE.md`).
- Try a build on the MiSTer without installing it: `MISTER=root@<address> tools/test_on_mister.sh <id>|list|nodata|log|stop` (the rule in `hybrid/CLAUDE.md`).
- Lines marked `GAME:` in the scripts and `TODO` in the READMEs are the places the template left for this game.

## Quake

- The port is [Chocolate Quake](https://github.com/Henrique194/chocolate-quake) (vanilla Quake 1.09, software renderer), chosen 2026-10-24 for its vanilla features and speed: on the PC its engine took 0.278 ms a frame of demo1 at 320x200, TyrQuake 0.346, qrustyquake 0.350. Local only for now: `chocolatequake/` is a clone of upstream (edb8209) on branch `mister`, its remote `/home/danik/chocolate-quake`; no fork or repository on GitHub (Danik, 2026-10-24).
- Games (ids are Danik's logo names): `QUAKE` (id1), `HIPNOTIC` (Scourge of Armagon, `-hipnotic`), `ROGUE` (Dissolution of Eternity, `-rogue`); the shareware (id1/pak0.pak alone) has no menu entry, the `QUAKE` entry starts it (`MH_PickGame()`'s `shareware_of`). The mission packs need the full id1. `MiSTer_SelectGame()` adds `-basedir .` and the pack's option. Paks are found in any case (`ID1/PAK0.PAK` of CD and shop copies: `COM_FindCase()` in `com_fs.c`). The 2021 rerelease's own paks are not what this engine reads; its folder of the original files is (Danik accepted that, 2026-10-24).
- Video (`src/video/src/vid_mister.c` in place of the renderer code): the window surface in 8 bits (`SDL_MISTER_VIDEO_FORMAT=INDEX8`) is `vid.buffer` itself, which keeps its pixels as Quake needs. The OSD's *Resolution* (bits 24..25: 320x200, 640x200, 320x240, 640x240) is read every frame and changes the mode at once. In the 640-wide modes the 3D view has twice the detail and the 2D (status bar, console, menus, centre prints) is laid out in `vid.width2d` (320) and drawn twice as wide (`Draw_WideBlock()` in `draw.c`); the full-screen routines (tile clear, fade, console background) stay in real pixels.
- 240 lines (`vid.hud_over_view`): the view fills the screen (`VID_VIEW_SB_LINES()`: no lines left to the status bar), the status bar and inventory are drawn over it every frame at the bottom HUD margin (`vid.hud_bottom`), the console's notify lines, the chat line and the ram/net/turtle icons at the top one (`vid.hud_top`). Both HUD lines (Danik, 2026-10-24: top the console and its messages, bottom the status bar), greyed out with mask bit 0 in the 200-line modes. Menus keep Quake's layout from the top of the screen.
- Input: the MiSTer joystick is mapped as a game controller (`IN_AddMiSTerMappings()` in `in_gamepad.c`) and opened at the start (it was there before the mapping, no event says so). The core's buttons bind as Quake keys (`MiSTer_PadBindings()`, run after `default.cfg`, before `config.cfg`): A jump, B swim down, X / Y next / previous weapon (impulse 10 / 12), L and L2 run, R and R2 attack, R3 centerview, Select scores, Start the menu. In menus the game's buttons do nothing (Menu OK / Back are the paddles, K_ENTER / K_ESCAPE, nothing in the game), except while *Customize controls* waits for a button; Menu OK also answers Quake's two questions (new game, quit). MiSTer presses the d-pad with the stick: a d-pad press in the game is dropped while the stick points its way, and the stick's own d-pad emulation is off.
- Cheats (`Host_MiSTerCheats()` in `host_cmd.c`, single player only): *God Mode*, *No Clipping*, *Invisible to Monsters* (bits 28..30) run Quake's commands on the local server when the player's state differs, again on every level; triggers *All Weapons and Keys* (impulse 9), *Quad Damage* (impulse 255), *Full Health and Armor* (100 health, 200 red armor; rogue's armor bits), *Next Level* (the level's trigger_changelevel whose map comes first by name: not the secret exit, episode 1 from the start map). All four tried in both mission packs on the PC (2026-10-24).
- Rumble (*Rumble* On / Strong / Off, bits 26..27): hits (`V_ParseDamage`), shots (the view's kick, `punchangle`, heavier for the launchers), landings (land.wav / land2.wav on the player), explosions by distance (`cl_tent.c`); jolts fade out (`MiSTer_Rumble()`), none during demos.
- Music: Chocolate Quake plays CD tracks from `music/trackNN.ogg|mp3|flac|wav`; libvorbis, libFLAC and libmad are not on the MiSTer, so `snd_mister.c` decodes with SDL2_mixer's single-file decoders (stb_vorbis, dr_flac, minimp3, `MISTER_CODECS`). No MIDI: `MIDI_SYNTH` 0.
- `MISTER_HYBRID_FPSLOG=1` prints where a frame's time goes (`MiSTer_Mark()` in `host.c` and `screen.c`).
- **Frame pacing** (the rule in `hybrid/CLAUDE.md`; 2026-10-24, demo1's first 50 seconds after the first 5, `MISTER_HYBRID_PACE=1`, runs in turns): at 640x240, without drawing ahead (`MISTER_HYBRID_AHEAD=0`) 199 / 202 frames never shown and 525 / 526 shown twice, with it 40 / 36 and 372 / 363; the render took 16.1 ms a frame on average (slowest about 40 ms). **`DRAW_AHEAD` 1.** Frames per second with it: 320x200 59.6, 320x240 59.2 (render 11.5 ms), 640x200 58.1 (12.0 ms), 640x240 53.5. The renderer is Chocolate Quake's C, without DOS Quake's x86 assembly.
